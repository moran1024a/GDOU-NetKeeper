# GDOU NetKeeper

Linux SRUN 校园网认证服务，兼容 Ubuntu 24.04，支持有线、Wi-Fi 和指定网卡。
提供终端菜单、认证参数识别、主动注销、公网与内网主备探测，由 systemd 管理后台进程。

## 安装与使用

从 [Releases](https://github.com/moran1024a/GDOU-NetKeeper/releases) 下载 `.deb` 和 `.deb.sha256`，放在同一目录校验并安装：

```bash
sha256sum -c gdou-netkeeper_0.3.5-1_amd64.deb.sha256
sudo apt install ./gdou-netkeeper_0.3.5-1_amd64.deb
sudo netkeeper
```

首次运行或启动时配置无效，会进入设置，保存后检查校园网环境并启动。
账号填写完整后缀；选择网卡后，Portal 和 `ac_id` 在自动模式可以留空。
菜单使用 ↑↓ / Tab 选择、Enter 确认、Esc 返回；输入支持光标移动、删除、粘贴和 Ctrl+U 清空。
所有输入均明文显示，包括密码。设置修改先暂存，主菜单“保存配置”后才写入文件。

| 命令 | 行为 |
| --- | --- |
| `sudo netkeeper start` | 等待确认校园网已在线，成功后退出前台，后台继续工作 |
| `sudo netkeeper stop` | 停止全部请求、巡检和重试；不注销校园网 |
| `sudo netkeeper logout` | 停止服务并注销当前校园网登录；之后保持停止 |
| `netkeeper status` | 查看进程、网卡、最近公网/内网探测、认证结果及下次检查时间，不发起网络请求 |
| `sudo netkeeper settings` | 修改配置；运行中可选择立即重启应用，或下次启动生效 |

首次启动最多等待 45 秒。确认已在线包括 Portal 明确在线，或可信内网目标可达且 Portal 没有明确否定。
只有普通公网可达不能算启动成功。失败、超时或取消会说明原因，并停止本次新启动的服务。
重复 `start` 不创建新进程，也不绕过正在等待的重试期限；失败或取消时保留原有服务。
退出菜单和断开 SSH 不停止后台服务。

## 探测与环境判断

公网、内网各有 1 个主目标和最多 3 个可选备用目标。先检查主目标，失败后并发检查备用；任意一个成功即整组成功。
每个目标单独选择 ICMP、TCP 或 HTTPS。ICMP 使用 IPv4；TCP/HTTPS 可填写 IPv4 或域名并指定端口。
HTTPS 只完成 TLS 握手并校验证书可信、域名匹配及有效期，不下载页面、不跟随跳转，不要求 HTTP 200。
普通探测默认超时 1 秒，HTTPS 默认 3 秒；超时包含解析、连接和握手。
所有配置的内网目标均视为可信校园网目标，用户负责选择符合实际环境的地址。

| 组别 | 主目标 | 备用目标 |
| --- | --- | --- |
| 公网 | ICMP `223.5.5.5` | ICMP `119.29.29.29`、`180.76.76.76`、`223.6.6.6` |
| 内网 | TCP `210.38.139.41:8081` | HTTPS `jw.gdou.edu.cn:443`、`kjcrms.gdou.edu.cn:443`，第三项留空 |

设置菜单可编辑每个目标的类型、地址、端口，移除备用目标或恢复本组默认值。
域名由系统 DNS 解析，实际探测和认证连接绑定所选网卡；不会切换其他出口，不修改网络拓扑或 DNS 配置。
网卡不存在、未连接、没有 IPv4 或路由时，先报告本地问题，不发送认证请求。

| 公网 | 内网 | 处理 |
| --- | --- | --- |
| 可达 | 可达 | 视为已认证校园网，正常运行 |
| 可达 | 不可达 | 复核 Portal；无法确认校园网则等待，不提交登录 |
| 不可达 | 可达 | 复核 Portal；没有明确掉认证时视为出口故障，不重复登录 |
| 不可达 | 不可达 | 查询 Portal、检查 HTTP 认证跳转；确认未认证后才登录，否则等待 |

Portal 明确结果优先：在线时不重复登录，离线时进入认证流程；在线账号不匹配则暂停，不切换或注销其他账号。
运行中公网默认每 2 秒探测，连续 3 轮全部失败后升级检查；内网默认每 30 秒探测，整组失败一轮就升级检查。
网卡或出口 IPv4 变化时提前重新检查。Portal 正常巡检间隔保留 300 秒。
已启动的服务遇到环境未知、网卡断开或校园网出口故障，每 30 秒复查。
只有需要认证的恢复失败才使用 **5 秒 × 前三次 → 15 秒 × 随后三次 → 持续 30 秒**退避，等待从本轮结束后计算。
明确账号密码错误会暂停自动请求，修改配置并重启后恢复。
探测与认证统一调度，不重叠登录，不补跑积压轮询；运行中的每次完整检查也有 45 秒上限，可随时停止。
各组间隔、超时、连续失败门槛、环境复查及认证重试间隔均可修改。

## 认证参数与注销

自动模式在每次确认掉认证后，从当前网卡的公网 HTTP 认证跳转重新获取 Portal 和 `ac_id`。
最多读取 6 个页面、等待 10 秒；支持 HTTP 及常见 HTML/JavaScript 跳转文字，不执行页面脚本。
只接受明确的编号，不从 Portal 通用首页选默认编号，不凭 `index_24.html` 文件名猜编号。
识别失败不沿用旧编号提交登录；同一轮恢复可复用刚识别的参数。出口 IP 改变时参数失效；已知接入点拒绝触发重新识别，两次识别至少间隔 30 秒。
手动模式始终使用填写的 Portal 和 `ac_id`。

设置提供“自动识别 Portal / ac_id”和“从认证页面链接导入”。已经在线时不会为了识别参数主动注销；未知参数显示待确认。
自动模式中已有 Portal 只作为查询提示，保存的编号不固定用于下次登录。
登录被接受后最多检查 3 次在线状态，必要时相隔 1 秒，不重复提交登录。

注销先读取实际会话并停止服务，再核对当前出口 IPv4 和服务器在线账号；不使用修改后尚未生效的账号或网卡替换原会话。
缺少可靠参数、账号不符、出口变化或服务未能停止时不发送注销。
已有会话仅缺编号时，可用相同网卡、账号及 Portal 的明确手动配置补足；没有会话记录时须提供完整手动配置。
只发送一次注销，随后最多查询 3 次确认；失败或无法确认时服务仍停止。网络不通不能视为注销成功。
TUI 注销需确认，命令行 `logout` 直接执行；依赖校园网出口的 SSH 可能因此断开。

## 进程恢复与数据

首次安装不启动服务。安装和升级均关闭本程序历史开机自启设置，不提供开机启动入口。
系统重启或断电后服务保持关闭，必须再次手动 `start`；升级仅重启原本正在运行的服务。

成功启动后，systemd 会在进程异常退出、被 SIGKILL 或 SIGTERM 终止后自动恢复，等待从 5 秒逐步增加至 30 秒。
显式 `stop/logout`、首次启动失败不会自动恢复。恢复中的服务即使暂时断网也继续等待，不按首次启动失败退出。
运行标记、暂停状态和重试期限在同一次开机的进程重启间保留；开始网络操作前预留恢复期限，防止异常退出绕过退避。
`stop` 和系统重启清除运行状态。不会依靠历史 PID 或旧在线标记跳过真实检查。

配置保存在 `/etc/netkeeper/config.toml`，权限 `0600`，采用原子替换与同步写入。
实际会话保存在 `/var/lib/netkeeper/session.json`，文件 `0600`、目录 `0700`，不包含密码；损坏缓存不会阻止重新启动。
会话记录用于安全注销和 Portal 查询提示，不作为旧 `ac_id` 自动登录兜底。确认注销或 purge 时清理。
运行状态在 `/run/netkeeper`，由 systemd 管理；普通用户通过 `netkeeper status` 查看不含密码的状态。

旧版公网配置（IPv4 字符串、整组 `mode/tcp_port`）自动转换，保存时写成逐目标格式。
缺少内网配置和新字段时使用默认值，原账号、网卡及用户探测设置保留。
非交互环境支持所有非设置命令；配置无效时提示先在终端完成设置。

错误信息区分网卡/路由、DNS、TCP、TLS/证书、参数识别、Challenge、登录确认和注销阶段。
查看日志：`journalctl -u netkeeper`。卸载：`sudo apt remove gdou-netkeeper`；删除配置和记录：`sudo apt purge gdou-netkeeper`。

## 构建

需要 Rust stable、Python 3.11+、C 链接器、`dpkg-dev` 和 `iputils-ping`，在 Ubuntu 24.04 原生构建。

```bash
cargo build --locked
python3 packaging/build-deb.py
```

安装包和 SHA-256 文件输出到 `dist/`，支持原生 amd64 / arm64 构建。运行时无需 Rust 工具链。
依赖已缓存时可用 `python3 packaging/build-deb.py --offline`。仅支持 IPv4，不管理 Wi-Fi 接入或系统网络配置。
